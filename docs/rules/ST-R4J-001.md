# ST-R4J-001: Retry without exponential backoff or jitter

| | |
|---|---|
| **Severity** | WARNING |
| **Applies when** | `resilience4j.retry.instances.*` is configured. |
| **Options** | none. |

## What it detects

An instance whose effective configuration (instance, else `base-config`, else `configs.default`) has `max-attempts` > 1 (default 3) and neither `enable-exponential-backoff` nor `enable-randomized-wait`.

## Why it matters

When a dependency degrades, every client retries in lock-step at the same interval. Each failure becomes N requests at the worst moment, which delays recovery (a retry storm).

## Example

Flagged:

```yaml
resilience4j.retry.instances.payments.max-attempts: 5
```

Fixed:

```yaml
resilience4j.retry.instances.payments:
  max-attempts: 3
  enable-exponential-backoff: true
  exponential-backoff-multiplier: 2
  enable-randomized-wait: true
```

## Suppress

```yaml
# springtune.yml
suppress:
  - rule: ST-R4J-001
    module: my-service        # optional
    reason: "Why this is acceptable here"   # required
```
