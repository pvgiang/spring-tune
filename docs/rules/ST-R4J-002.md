# ST-R4J-002: Circuit breaker blind to slow calls

| | |
|---|---|
| **Severity** | WARNING |
| **Applies when** | `resilience4j.circuitbreaker.instances.*` is configured. |
| **Options** | none. |

## What it detects

An instance with no `resilience4j.timelimiter.instances.<same name>` (nor `timelimiter.configs.default`) and no effective slow-call detection: `slow-call-duration-threshold` unset (default 60 s) or `slow-call-rate-threshold` at its default of 100%.

## Why it matters

Calls that hang are neither failures nor 'slow' under these settings, so the breaker stays closed while every caller thread waits. It protects only against fast failures, the case that needs protection least.

## Example

Flagged:

```yaml
resilience4j.circuitbreaker.instances.gateway.failure-rate-threshold: 50
```

Fixed:

```yaml
resilience4j.circuitbreaker.instances.gateway:
  failure-rate-threshold: 50
  slow-call-duration-threshold: 2s
  slow-call-rate-threshold: 50
```

## Suppress

```yaml
# springtune.yml
suppress:
  - rule: ST-R4J-002
    module: my-service        # optional
    reason: "Why this is acceptable here"   # required
```
