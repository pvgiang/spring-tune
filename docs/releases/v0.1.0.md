First public release of SpringTune: catch the Spring Boot configuration that will take you down, before production does.

## What's in it

- **`springtune check`**: a CLI, a Maven plugin and a GitHub Action. They run 13 static rules over
  `application*.yml/properties` (resolved with Spring Boot's own loaders: profiles, relaxed names,
  placeholders), Java sources and Helm/Kubernetes manifests. The rules cover connection-pool exhaustion
  (HikariCP timeouts, leak detection, max lifetime, fleet-wide connection budget), Tomcat threads vs pool,
  unbounded `@Async` executors, HTTP clients without timeouts, Feign defaults, transaction timeouts, and
  Resilience4j retry and circuit-breaker settings. Output is text, Markdown, JSON or SARIF, and the build
  fails at a severity you choose.
- **`springtune-spring-boot-starter`** (read-only): `/actuator/tuning` shows live HikariCP and
  `ThreadPoolTaskExecutor` knobs, signals, and explained, budget-capped recommendations. It never changes
  anything.

## Measured precision

On 20 public Spring Boot repositories (282 modules): **199 findings, 1 false positive (0.5%)**. See the
[corpus report](https://github.com/pvgiang/spring-tune/blob/main/docs/corpus/2026-11-corpus-report.md).

| `springtune-maven-repo-0.1.0.zip` | Maven repository layout with the plugin, starter and libraries (`io.github.winky.springtune:*:0.1.0`). Unzip it and use it as a file repository until Maven Central publishing is set up |
| `SHA256SUMS` | Checksums of the files above |

## GitHub Action

```yaml
- uses: pvgiang/spring-tune@v0.1.0
  id: springtune
  with:
    profile: prod
- uses: github/codeql-action/upload-sarif@v3
  if: always()
  with:
    sarif_file: ${{ steps.springtune.outputs.sarif }}
```

## Compatibility

JDK 17, 21 and 25. The starter works with Spring Boot 4.1 and 3.5. The check analyzes Spring Boot 1.x to 4.x
projects, using Boot 2.4+ config semantics.

## Known limitations

- **Not on Maven Central yet:** use the zip repository above.
- **Not analyzed:** environment variables, remote config (Config Server, Nacos) and Kotlin sources. Modules
  whose config is remote are reported as *not evaluated* rather than guessed.
- **Not included yet:** `apply` mode, the adaptive concurrency limiter, and a Gradle plugin.
