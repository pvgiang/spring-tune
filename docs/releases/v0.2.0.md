SpringTune 0.2.0 adds a Gradle plugin.

## What's new

- **Gradle plugin `io.github.winky.springtune`** (Gradle 8.5+, configuration cache compatible). It registers
  `springtuneCheck` and wires it into `check`, with the same 13 rules, reports and `springtune.yml` as the CLI and
  Maven plugin. Configure it in a `springtune { }` block or with `-Pspringtune.*`.
  - **Sees what Gradle resolves.** The resolved runtime classpath and Spring Boot version decide which rules
    apply, so dependencies declared through version catalogs, convention plugins or BOMs are no longer
    invisible. If a dependency cannot be resolved, the task says so.
  - **Isolated.** The plugin jar has no dependencies. The engine runs in a Gradle worker with its own class
    loader, so it never clashes with the Spring Boot Gradle plugin.
- **Engine API:** `CheckRequest` accepts per-module `ResolvedBuild` facts from the calling build tool.
- **Leaner POMs:** model, engine and the Gradle plugin are published with flattened POMs (no parent, no BOM
  imports).

## Using the Gradle plugin from the release

Until the plugin is on the Gradle Plugin Portal, unzip `springtune-maven-repo-0.2.0.zip` and add it to both
`pluginManagement.repositories` (for the plugin) and `repositories` (for the engine). Then:

```kotlin
plugins {
    id("io.github.winky.springtune") version "0.2.0"
}
```

Details: [docs/check.md#gradle-plugin](https://github.com/pvgiang/spring-tune/blob/main/docs/check.md#gradle-plugin).

| File | Use |

| `springtune-maven-repo-0.2.0.zip` | Maven repository with the Maven plugin, Gradle plugin (and marker), starter and libraries (`io.github.winky.springtune:*:0.2.0`) |
| `SHA256SUMS` | Checksums of the files above |

## Compatibility

JDK 17, 21 and 25. Gradle plugin: tested with Gradle 8.5, 8.14 and 9.8. The starter works with Spring Boot 4.1
and 3.5. The check analyzes Spring Boot 1.x to 4.x projects, using Boot 2.4+ config semantics.

## Known limitations

- Not on Maven Central or the Gradle Plugin Portal yet: use the zip repository above.
- `springtuneCheck` is never up-to-date (it reads files anywhere below the root project).
- Unchanged from 0.1.0: environment variables, remote config and Kotlin sources are not analyzed; no `apply`
  mode or adaptive limiter yet.
